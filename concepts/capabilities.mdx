A **capability** is something this SDK build can do. In v1 that set is fixed: [control-point](/concepts/control-points) reads and [target registration](/concepts/targeting).

<Warning>
  The SDK `capabilities` namespace (`get`, `list`, `invoke`) was **removed in v1** ([ADR-0010](https://github.com/FireWeave-HQ/fireweave-sdk/blob/master/docs/adr/0010-control-points-only-v1.md)). `conformance/surface/control-points.surface.json` asserts the client must not expose `capabilities`. Do not sniff versions or call `capabilities.get()`. See [Migrate 2.1 to 2.3](/migration/v1).
</Warning>

## Why this page still exists

Language surfaces no longer diverge on the v1 path. All seven SDKs expose the same nine control-point methods and `registerTarget`. You do not need a discovery matrix to know whether registration exists.

`capabilities.features.flags` remains `true` at the **conformance / envelope boundary**. Removing the OpenFeature dependency did not rename that pin. The product noun is still control point.

## What v1 does not expose

| Former capability | v1 status |
|-------------------|-----------|
| `releases.*` | Removed. [Releases](/concepts/releases) remain a platform concept |
| `exposures.*` | Removed. [Exposures](/concepts/exposures) remain a platform concept |
| `signals.*` | Removed. [Signals](/concepts/signals) remain a platform concept |
| `capabilities.get` | Removed |
| OpenFeature provider | Unbundled. See [OpenFeature](/openfeature) |
| Guardrails | **No SDK API.** Guardrails are platform-managed in the Fireweave console. The typed stub that returned `UnsupportedCapability` is gone |

Do not document console guardrail connectors, soak checks, or thresholds on this site. The SDK does not evaluate them.

## `UnsupportedCapability`

The 15-kind error taxonomy still includes `UnsupportedCapability` ([Errors](/production/errors)). In v1 you see it when a custom adapter lacks `registerTarget`, or when `InMemoryAdapter` is asked to register a target. You do not see it from a `guardrails` stub — that stub is gone, so the import fails at build time.
