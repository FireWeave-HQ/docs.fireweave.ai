There is no ship command. A pull request into an environment branch is the ship: Fireweave checks it, merging it registers a rollout, and a person starts that rollout after the deploy.

## Stages

| Stage | What happens | Who acts |
| --- | --- | --- |
| Prepare | The change sits behind a control point that defaults to off, with the metrics to watch recorded. | Your coding agent |
| Check | Fireweave posts **Fireweave — rollout readiness** on the pull request. See [PR check](/ship/pr-check). | Fireweave |
| Merge | You merge the pull request into an environment branch. | You |
| Register | Fireweave registers a rollout for the control points the merge brings, in the **first environment** of that branch. It shows as **Waiting for Start**. | Fireweave |
| Start | After your deploy, you press **Start rollout**. Nothing is exposed before this. | You |
| Ramp | Exposure rises stage by stage while guardrails are checked. See [Run a rollout](/ship/run-a-rollout). | Fireweave, or you on manual |
| Next environment | A completed rollout moves on by promotion, or by a merge into that environment's own branch. See [Promote and clean up](/ship/promote-and-clean-up). | You, or Fireweave on its own |

<Info>
- Merging into a branch that isn't an environment branch registers nothing. The rollout is registered when that work reaches an environment branch.
- Agents never register, start, ramp or promote rollouts.
- **Start rollout** is how you tell Fireweave your deploy is live.
</Info>
