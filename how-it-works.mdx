You set FireWeave up once per repository. After that, every feature follows the same path: your agent wraps it, you merge it, and you decide when it reaches users.

## The steps

| Step | What happens | Who |
| --- | --- | --- |
| Set up | FireWeave opens a setup PR in each repository; you merge it. | You |
| Build | Your agent, following FireWeave's instructions in the repo, wraps the change behind a control point and records what to watch. A check stops the agent if it skips this. | Your coding agent |
| Pull request | FireWeave reports readiness on the PR, and risk when PR analysis is on. | FireWeave |
| Merge | Merging into an environment branch registers a rollout. | You |
| Start | After your deploy, you press **Start rollout**. | You |
| Ramp | Exposure rises stage by stage while your metrics are checked. | FireWeave |
| Stable | After the stability soak at 100%, the control point is marked stable. In **Manual** mode you press **Mark stable now**. | FireWeave, or you |
| Clean up | Your agent removes the old code path in a later change. | You and your agent |

<Info>
**What FireWeave doesn't do**

- It doesn't detect your deploys. Pressing **Start rollout** tells FireWeave the code is live.
- Agents never register, start, ramp or promote rollouts.
- Nothing reaches users until you press **Start rollout**: a new control point starts off.
</Info>
