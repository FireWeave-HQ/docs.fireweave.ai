## Evaluation types

The wire uses `flagKey`. Native product noun is **control point**.

| | Native evaluate | Boolean | String | Number | Object |
| --- | --- | --- | --- | --- | --- |
| Node | `client.controlPoints.*` | `getBooleanValue` | `getStringValue` | IEEE-754 `number` | `getObjectValue` |
| Python | `client.control_points.*` | `get_boolean_value` | `get_string_value` | `get_number_value` | `get_object_value` |
| Go | `client.ControlPoints()` | `GetBooleanValue` | `GetStringValue` | `GetNumberValue` (`float64`) | `GetObjectValue` |
| Java | `client.controlPoints()` | `getBooleanValue` | `getStringValue` | `getNumberValue` (`double`) | `getObjectValue` |
| Web | `client.controlPoints.*` (**sync**) | `getBooleanValue` | `getStringValue` | IEEE-754 `number` | `getObjectValue` |
| Rust | `client.control_points.*` | `get_boolean_value` | `get_string_value` | `get_number_value` | `get_object_value` |

Each language also ships the four `*Details` methods plus `evaluate`. That is the nine-method surface in `conformance/surface/control-points.surface.json`.

### Numeric limitations

| Language | Limitation |
| --- | --- |
| Node / Web | Single IEEE-754 double. Integers beyond ±(2^53−1) are not lossless. |
| All | Canonical JSON numbers. Cross-language integer reliability within ±(2^53−1). |

Python `get_integer_value` is a deprecated alias of `get_number_value`. Go and Java no longer split integer/float on the native surface (`FlagTypeNumber` / `FlagType.NUMBER` only).

## Conformance

The suite is a **65×7 aggregate**: the same 65 fixtures run against all seven language bindings (`scripts/conformance-all.sh`). Surface parity (the nine methods plus `registerTarget`) is green for node, web, python, java, go, rust, and swift.

All behavioural skips, when present, are pre-declared (`skipped-with-documented-limitation`). Node/Web IEEE-754 integer fixtures are the documented numeric limitation.

## Server vs web

| | Server SDKs | Web |
| --- | --- | --- |
| `controlPoints.*` | Promise / blocking | **synchronous** |
| Evaluation source | per-call (remote) | prefetched cache |
| Extra lifecycle | — | **STALE** (5s prefetch ceiling) |
| Config | explicit init options | explicit init options |

## Known gaps (do not paper over)

1. **Swift is not distributable** — in-tree only; SwiftPM cannot resolve `Package.swift` from the repository URL.
2. **Java leftover artifacts** — `fireweave-openfeature`, `fireweave-adapter-posthog`, and `fireweave-testing` stay at 0.1.0. They are not the 2.3.0 SDK.
3. **OpenFeature is unbundled** — no core SDK ships a provider. A future optional bridge is not forbidden; it is not published as part of 2.3.0.
