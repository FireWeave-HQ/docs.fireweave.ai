Every SDK reads control points with the same nine methods and registers targets, under its own language's naming. Every SDK is published at **3.1.0**.

## What each SDK supports

| | Node | Web | Python | Go | Java | Rust | Dart | Swift |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Start profile | Server | App | Server | Server | Server | Server | App and server | App and server |
| Reads | Async, per call | Sync, from cache | Blocking, per call | Blocking, per call | Blocking, per call | Blocking, per call | Sync, from cache | Sync, from cache |
| Local mode | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Register targets (`identify`) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| In-memory adapter for tests | ✓ | ✓ | ✓ | ✓ | — | ✓ | ✓ | ✓ |

Server reads ask FireWeave on each call. Browser and mobile apps fetch decisions for the signed-in user up front, so reads are instant and safe in a render path. Dart and Swift servers refresh their decisions every 30 seconds.

<Note>
The SDKs ship control points and target registration only. Guardrails, metrics and rollout control live in the web app, not in the SDK.
</Note>

## Numbers

Node and Web hold numbers as JavaScript doubles: integers beyond ±(2^53−1) lose precision. Keep numeric values inside that range for the same result in every language.
