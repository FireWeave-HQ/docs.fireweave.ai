The `fireweave` package reads control points and registers targets from Python `>=3.10`. It has no runtime dependencies.

```bash
pip install fireweave
```

## Start profile

Call `start()` once, first thing in each process entrypoint, then read through `fw` anywhere.

<CodeGroup>

```python control_points.py
from fireweave.start import define_control_points

# Local values only. In production the rollout decides.
control_points = define_control_points({"new-checkout": {"local": True}})
```

```python entrypoint
from fireweave.start import start
from control_points import control_points

start(control_points=control_points)
```

```python anywhere
from fireweave import EvaluationContext
from fireweave.start import fw

if fw.control_points.get_boolean_value("new-checkout", False, EvaluationContext(user.id)):
    ...  # new path
```

</CodeGroup>

| Variable | What it does |
| --- | --- |
| `FIREWEAVE_KEY` | The server key (`project-api-key_…`). Set means remote mode. |
| `FIREWEAVE_URL` | Optional. Overrides the Fireweave endpoint. |
| `FIREWEAVE_ENV`, then `APP_ENV` | With no key, `development`, `dev`, `local` or `test` means local mode. Anything else, or no name at all, fails at start. |

Every option is keyword-only, among them `control_points`, `mode`, `environment`, `url`, `key` and `instance_id`. `fw` also has `identify(targeting_key, properties)`, `instance_key()` for reads with no user, `status()` and `shutdown()`. A forked worker gets its own client. Rules for every SDK: [Start profile](/sdks/start-profile).

## Core API

`init_fireweave` reads no environment. `mode` is required.

```python
import os
from fireweave import EvaluationContext, RegisterTargetOptions, init_fireweave

client = init_fireweave(
    mode="remote",  # or mode="local", local={"control_points": {"new-checkout": True}}
    api_url="https://app-server.fireweave.ai",
    api_key=os.environ["FIREWEAVE_KEY"],
)

client.register_target("user_42", RegisterTargetOptions(kind="user", properties={"plan": "pro"}))

on = client.control_points.get_boolean_value("new-checkout", False, EvaluationContext("user_42"))
```

`control_points` has nine methods, and none of them raises:

| Values | Details (whole `Decision`) |
| --- | --- |
| `get_boolean_value` | `get_boolean_details` |
| `get_string_value` | `get_string_details` |
| `get_number_value` | `get_number_details` |
| `get_object_value` | `get_object_details` |
| `evaluate(key, FlagType.BOOLEAN, default, context)` | |

A `Decision` carries `value`, `reason`, `control_point_metadata` and, on failure, `error_kind`. `register_target` returns `ok=False` instead of raising.

## Errors and shutdown

A read that fails returns your default. Configuration problems raise `ConfigurationError` at start. Every error subclasses `FireweaveError`, for example `ControlPointNotFoundError`: see [Errors and lifecycle](/sdks/errors-and-lifecycle).

```python
fw.shutdown()  # or client.shutdown()
```
