---
title: "Java"
description: "Install the FireWeave Java SDK, start it in one line and read control points."
---

The Java SDK is `ai.fireweave:fireweave-sdk` on Maven Central. Its `ai.fireweave.sdk.start.Fw` class is the [start profile](/sdks/start-profile): one call in `main`, then reads from anywhere.

<Steps>
  <Step title="Install">
    <CodeGroup>
    ```xml Maven
    <dependency>
      <groupId>ai.fireweave</groupId>
      <artifactId>fireweave-sdk</artifactId>
      <version>3.1.0</version>
    </dependency>
    ```
    ```kotlin Gradle
    implementation("ai.fireweave:fireweave-sdk:3.1.0")
    ```
    </CodeGroup>
    Pin an exact version. A version range can resolve a release candidate, which calls FireWeave's staging server.
  </Step>
  <Step title="Declare your control points">
    ```java FireweaveControlPoints.java
    // Every control point the app reads, with the value served in local mode.
    public static final LocalControlPoints CONTROL_POINTS = Fw.defineControlPoints(Map.of(
            "new-checkout", LocalControlPoint.local(true, "new checkout flow")));
    ```
  </Step>
  <Step title="Start once in main">
    ```java
    Fw.start(StartOptions.builder()
            .controlPoints(FireweaveControlPoints.CONTROL_POINTS)
            .build());
    ```
  </Step>
  <Step title="Read a control point">
    ```java
    // @fireweave-controlpoint new-checkout
    if (Fw.controlPoints().getBooleanValue("new-checkout", false,
            EvaluationContext.builder().targetingKey(user.id()).build())) {
        // new path
    }
    ```
    Reads never throw. If start failed, they return your default.
  </Step>
</Steps>

## Configuration

| Variable | Value |
| --- | --- |
| `FIREWEAVE_KEY` | Your project key (`project-api-key_…`). Set it in every deployed environment. |
| `FIREWEAVE_ENV`, then `APP_ENV` | `development`, `dev`, `local` or `test` with no key runs local. |
| `FIREWEAVE_URL` | Optional. Overrides the default endpoint. |

With no key outside a development environment, `Fw.start` throws a configuration error naming `FIREWEAVE_KEY`. It does no network I/O.

## Identify users

At sign-in, register the facts your targeting matches on:

```java
Fw.identify(user.id(), Map.of("plan", user.plan()));
```

`identify` never throws. In remote mode it is one blocking request, so call it off the request path when latency matters.

## Status and shutdown

- `Fw.status()` reports the mode and why, the channel, endpoint and key source. It never contains the key.
- `Fw.shutdown()` stops the client. Use it rather than `Fw.client().close()`. No JVM shutdown hook is registered for you.

<Note>
  `Fw.client()` returns the one `FireweaveClient` for the JVM, for dependency injection. To configure the client yourself with no environment reads, use `Fireweave.init(InitOptions…)`.
</Note>
