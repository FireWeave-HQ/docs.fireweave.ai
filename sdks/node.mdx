`@fireweaveai/server-sdk` reads control points and registers targets from server code. One package covers Node.js (`>=20.20`), Bun and Deno, with no runtime dependencies.

```bash
npm install @fireweaveai/server-sdk
# bun add @fireweaveai/server-sdk
# deno add npm:@fireweaveai/server-sdk
```

<Note>
Jest, NestJS-style TypeScript or Node 21 / 22.0–22.11 failing on an ES module? See [CommonJS projects](/sdks/commonjs).
</Note>

## Start profile

Start FireWeave once, as the first import of your entrypoint, then read through `fw` anywhere.

<CodeGroup>

```ts src/fireweave/control-points.ts
import { defineControlPoints } from '@fireweaveai/server-sdk/start';

// Local values only. In production the rollout decides.
export const controlPoints = defineControlPoints({
  'new-checkout': { local: true },
});
```

```ts src/fireweave/start.ts
import { start } from '@fireweaveai/server-sdk/start';
import { controlPoints } from './control-points';

start({ controlPoints });
```

```ts anywhere
import { fw } from '@fireweaveai/server-sdk/start';

if (await fw.controlPoints.getBooleanValue('new-checkout', false, { targetingKey: user.id })) {
  // new path
}
```

</CodeGroup>

| Variable | What it does |
| --- | --- |
| `FIREWEAVE_KEY` | The server key (`project-api-key_…`). Set means remote mode. |
| `FIREWEAVE_URL` | Optional. Overrides the FireWeave endpoint. |
| `FIREWEAVE_ENV`, then `APP_ENV`, then `NODE_ENV` | With no key, `development`, `dev`, `local` or `test` means local mode. Anything else, or no name at all, fails at start. |

No options to pass? Import `@fireweaveai/server-sdk/register` as your first import, or run `node --import @fireweaveai/server-sdk/register app.js`.

`fw` also has `identify(targetingKey, properties)`, `instanceKey()` for reads with no user, `status()` and `shutdown()`. Rules for every SDK: [Start profile](/sdks/start-profile).

## Core API

`initFireweave` reads no environment. `mode` is required.

```ts
import { initFireweave } from '@fireweaveai/server-sdk';

const fireweave = await initFireweave({
  mode: 'remote', // or 'local' with local: { controlPoints: { 'new-checkout': true } }
  apiUrl: 'https://app-server.fireweave.ai',
  apiKey: process.env.FIREWEAVE_KEY!,
});

await fireweave.registerTarget('user_42', { kind: 'user', properties: { plan: 'pro' } });

const on = await fireweave.controlPoints.getBooleanValue('new-checkout', false, {
  targetingKey: 'user_42',
});
```

`controlPoints` has nine methods, and none of them throws:

| Values | Details (whole `Decision`) |
| --- | --- |
| `getBooleanValue` | `getBooleanDetails` |
| `getStringValue` | `getStringDetails` |
| `getNumberValue` | `getNumberDetails` |
| `getObjectValue` | `getObjectDetails` |
| `evaluate(key, type, default, context)` | |

A `Decision` carries `controlPointKey`, `value`, `reason` and, on failure, `errorKind`. `registerTarget` returns `{ ok, error? }` and never throws.

## Errors and shutdown

A read that fails returns your default. Configuration problems throw `FireweaveError` with kind `Configuration` at start. Other kinds include `ControlPointNotFound`, `Authentication` and `Network`: see [Errors and lifecycle](/sdks/errors-and-lifecycle).

```ts
await fw.shutdown(); // or fireweave.shutdown()
```
