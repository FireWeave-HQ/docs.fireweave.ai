`@fireweaveai/web-sdk` reads control points in the browser. Reads are synchronous, so they are safe inside a render. It has no runtime dependencies.

```bash
npm install @fireweaveai/web-sdk
```

<Note>
Tests in Jest, or a Vite 5 config loaded as CommonJS? See [CommonJS projects](/sdks/commonjs).
</Note>

<Warning>
  A browser holds only a browser key (`fw_public_…`). Never ship the server key (`project-api-key_…`): the Vite plugin fails a build that contains one. See [Keys](/connect/keys).
</Warning>

## Start profile

The build plugin injects the key and endpoint, `start()` runs first, and `fw` reads anywhere.

<CodeGroup>

```ts vite.config.ts
import { defineConfig } from 'vite';
import { fireweave } from '@fireweaveai/web-sdk/vite';

export default defineConfig({ plugins: [fireweave()] });
```

```ts src/fireweave/control-points.ts
import { defineControlPoints } from '@fireweaveai/web-sdk/start';

export const controlPoints = defineControlPoints({
  'new-checkout': { local: true },
});
```

```ts src/fireweave/start.ts
import { start } from '@fireweaveai/web-sdk/start';
import { controlPoints } from './control-points';

export const ready = start({ controlPoints });
```

```ts anywhere
import { fw } from '@fireweaveai/web-sdk/start';

if (fw.controlPoints.getBooleanValue('new-checkout', false)) {
  // new path
}
```

</CodeGroup>

The plugin reads these at build time. The browser reads no environment.

| Variable | What it does |
| --- | --- |
| `FIREWEAVE_BROWSER_KEY` | The browser key. Set means remote mode. |
| `FIREWEAVE_URL` | Optional. Overrides the Fireweave endpoint. |
| `FIREWEAVE_ENV`, then `APP_ENV` | With no key, `development`, `dev`, `local` or `test` means local mode. A production build with no key fails. |

Not on Vite? `fireweaveDefine()` from `@fireweaveai/web-sdk/define` runs the same check and returns the values for webpack, esbuild, Rollup or Next.js.

## Users

Reads use an anonymous device id until you identify the user.

| Call | When |
| --- | --- |
| `await fw.identify(userId, { plan: 'pro' })` | Sign-in or session restore. Registers the user and switches reads to them. |
| `await fw.reset()` | Sign-out. Back to the device id. |
| `fw.setPersistence('memory')`, `await fw.forget()` | Consent. Stop storing, or clear and start over. |

`fw` also has `ready`, `status()`, `subscribe(listener)` and `shutdown()`. A bad setup never crashes your app: reads serve defaults and `fw.status()` names the problem. Rules for every SDK: [Start profile](/sdks/start-profile).

## Core API

`initFireweave` reads no environment. `mode` is required.

```ts
import { initFireweave } from '@fireweaveai/web-sdk';

const fireweave = await initFireweave({
  mode: 'remote', // or 'local' with local: { controlPoints: { 'new-checkout': true } }
  apiUrl: 'https://app-server.fireweave.ai',
  apiKey: 'fw_public_…',
});

await fireweave.identify('user_42', { kind: 'user', properties: { plan: 'pro' } });
const on = fireweave.controlPoints.getBooleanValue('new-checkout', false);
```

`controlPoints` has the same nine methods as the server SDK (`get{Boolean,String,Number,Object}{Value,Details}` and `evaluate`), returning values directly. None of them throws. `registerTarget` registers without switching reads; `identify` does both.

## Errors and shutdown

A read that fails returns your default. After a failed re-fetch, the last good decisions keep serving with reason `STALE`. Error kinds, including `ControlPointNotFound`: [Errors and lifecycle](/sdks/errors-and-lifecycle).

```ts
await fw.shutdown(); // or fireweave.shutdown()
```
