`@fireweaveai/web-sdk` is the Fireweave **browser** binding. It evaluates **control points** synchronously from a prefetched cache and registers targets via `registerTarget` / `identify`. Those are the two v1 capabilities. The wire protocol still uses `flagKey`.

This is a different surface from [`@fireweaveai/server-sdk`](/sdks/node). It is not a Node, Bun, or Deno server target.

<Warning>
  Authenticate the web SDK with a `fw_public_` key scoped to `flags:evaluate` and `events:write`. Do not embed a secret or `attest:write` project key in a frontend bundle. Key families and issuance: [Configuration](/production/configuration).
</Warning>

## Supported runtime

| | Value |
| --- | --- |
| Package | `@fireweaveai/web-sdk` **2.3.0** |
| Target | Browser |
| Runtime deps | **none** |
| CI | Bun + happy-dom only |

It ships no server entry point, reads **no environment**, and imports no runtime built-ins.

## Install

```bash
npm install @fireweaveai/web-sdk
```

or `bun add @fireweaveai/web-sdk`.

## Initialize

`initFireweave` is the single entry point. `mode` is required and never inferred. Reads after init are **synchronous**.

```js
import { initFireweave } from '@fireweaveai/web-sdk';

const fireweave = await initFireweave({
  mode: 'remote',
  apiKey,
  apiUrl,
  context: { targetingKey: 'anonymous' },
});

// SYNCHRONOUS — no await, safe inside render.
const on = fireweave.controlPoints.getBooleanValue('new-checkout', false);
```

Local mode (no network, no credentials):

```js
const fireweave = await initFireweave({
  mode: 'local',
  local: { controlPoints: { 'new-checkout': true } },
});
```

A bad host or missing credential still **throws** at `initFireweave()`. `FireweaveWebRuntime.initialize()` itself is fail-open: a hung prefetch must not block app boot. When the initial prefetch loses its 5 second race (`DEFAULT_FLAGS_READY_TIMEOUT_MS`), the runtime serves defaults with reason `STALE`.

## Lifecycle and STALE

States include **`STALE`**: prefetch raced the 5 second ceiling and lost. Reads are defaults with reason `STALE`. Collapsing STALE into READY would make a timed-out boot indistinguishable from a successful one where every control point is off.

## Configuration and authentication

`apiUrl` and `apiKey` are required in remote mode. The package **reads no environment**.

```js
const fireweave = await initFireweave({
  mode: 'remote',
  apiUrl: 'https://app-server.fireweave.ai',
  apiKey: 'fw_public_…',
  context: { targetingKey: 'anonymous' },
});
```

Use a `fw_public_` key. The adapter rejects `phc_` / `phs_` / `phx_` shapes (`assertNotSecretKey`) with `Configuration`. Default allowlist: `app-server.fireweave.ai`, `staging-app-server.fireweave.ai`, loopback. `https` off-loopback; `http` on loopback only.

Auth: `Authorization: Bearer <key>`. Paths: `/v1/flags/evaluate`, `/v1/targets/register`.

See [Configuration and auth](/production/configuration).

## Targets: `registerTarget` and `identify`

Web exposes both. `registerTarget` matches the other languages. `identify` is the sign-in helper: it registers, then `setContext({ targetingKey })` so the next prefetch buckets on that id.

```js
const result = await fireweave.identify('user_42', {
  kind: 'user',
  properties: { plan: 'pro' },
});

// Same registration without the context refresh:
await fireweave.registerTarget('user_42', {
  kind: 'user',
  properties: { plan: 'pro' },
});
```

`identify` is not OpenFeature `identify` and not analytics `identify`. Options: `kind?: 'user' | 'device'`, `properties?`, `environment?`.

See [Targeting and targets](/concepts/targeting).

## Control points (synchronous)

`ExpectedFlagType`: `'boolean' | 'string' | 'number' | 'object'` — same IEEE-754 number model as Node.

```js
const on = fireweave.controlPoints.getBooleanValue('new-checkout', false, { targetingKey: 'user_42' });
const theme = fireweave.controlPoints.getStringValue('copy', 'classic', { targetingKey: 'user_42' });
const decision = fireweave.controlPoints.getBooleanDetails('new-checkout', false, { targetingKey: 'user_42' });
```

Nine methods, all **sync**. Evaluation **never throws**. `client.flags` is the same object as `client.controlPoints` (deprecated alias, silent at runtime).

See [Control points](/concepts/control-points).

## Adapters

| Adapter | Use |
| --- | --- |
| `FireweaveRemoteWebAdapter` | Production. `initFireweave({ mode: 'remote', … })` builds it. |
| `FireweaveLocalWebAdapter` | Dev boolean map. `initFireweave({ mode: 'local', … })` builds it. |
| `InMemoryWebAdapter` | Tests / fixtures. |

There is **no** vendor adapter and **no** in-process definition poll.

See [Adapters](/concepts/adapters).

## Errors

Same 15-kind `FireweaveError` taxonomy as the Node SDK. Evaluation never throws. Init throws on configuration failure.

See [Errors](/production/errors).

## Testing

`initFireweave({ mode: 'local', … })` or `InMemoryWebAdapter`. CI uses Bun and happy-dom.

See [Testing](/testing).

## Shutdown

```js
await fireweave.shutdown();
```

A tab has no process shutdown hook.

See [Initialize, ready, shutdown](/production/lifecycle).

## Not in this SDK

- `FireweaveWebProvider` / `@openfeature/web-sdk`
- `releases`, `exposures`, `signals`, `capabilities`, `guardrails`
- Environment-variable configuration
- A server entry point / Node-as-target
- Secret project keys in the browser
