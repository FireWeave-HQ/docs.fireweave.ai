title: "Testing"
description: "Deterministic Fireweave tests with InMemoryAdapter and local mode. The stub implements evaluate, capture, and /health — not /v1/targets/register."
---

Two Fireweave-provided tools mean unit and most integration tests never need a backend account:

1. **`mode: 'local'`** — seeded boolean map, no network, no credentials. `registerTarget` records in-process and traces.
2. **`InMemoryAdapter`** — fixture-driven adapter in every language. Use it when you need attribute match conditions, faults, or live mutation.

A third option when you need the real HTTP path: the **protocol test server** (`test-server/`).

<Warning>
  The test server does **not** implement `POST /v1/targets/register`. `InMemoryAdapter` also does not persist registration (`UnsupportedCapability`). Use local mode when the test must assert registration.
</Warning>

There is no `FireweaveProvider` and no `makeFireweaveLocalProvider`. Bind `FireweaveClient` (or `initFireweave`) to an adapter.

## Local mode

Present in all seven languages.

| Key | Result |
| --- | --- |
| Present in the seeded map | Mapped **boolean**, reason `STATIC` |
| Absent | Caller default, reason `DEFAULT` |

Reading a seeded key as a string or number is `TypeMismatch`. The map is boolean-only.

<Tabs>
  <Tab title="Node">
    ```ts
    import { initFireweave } from '@fireweaveai/server-sdk';

    const fireweave = await initFireweave({
      mode: 'local',
      local: { controlPoints: { 'new-checkout': true } },
    });

    const on = await fireweave.controlPoints.getBooleanValue('new-checkout', false, {
      targetingKey: 'u1',
    });
    // → true

    await fireweave.registerTarget('user_42'); // recorded + traced; nothing sent
    await fireweave.shutdown();
    ```

<Note>
  Call-site defaults stay `false`. Do not write `getBooleanValue(key, true)` to dogfood locally — that same `true` is the production fallback when a control point is absent.
</Note>

## InMemoryAdapter

Same conceptual fixture in every language: `type`, `enabled`, `value`, optional `variant`, and optional match conditions that gate on context attributes (no match → your default).

Java: artifact `ai.fireweave:fireweave-testing` (never published; `maven.deploy.skip=true`). Web: `InMemoryWebAdapter`.

<Tabs>
  <Tab title="Node">
    ```ts
    import { strict as assert } from 'node:assert';
    import { test } from 'node:test';
    import { FireweaveClient, FireweaveRuntime, InMemoryAdapter } from '@fireweaveai/server-sdk';

    test('beta cohort gets the new checkout', async () => {
      const adapter = new InMemoryAdapter({
        flags: {
          'new-checkout': {
            type: 'boolean',
            enabled: true,
            value: true,
            variant: 'on',
            matchAttribute: { cohort: 'beta' },
          },
        },
      });
      const runtime = new FireweaveRuntime(adapter);
      await runtime.initialize();
      const client = new FireweaveClient(runtime);

      assert.equal(
        await client.controlPoints.getBooleanValue('new-checkout', false, {
          targetingKey: 'u1',
          cohort: 'beta',
        }),
        true,
      );
      assert.equal(
        await client.controlPoints.getBooleanValue('new-checkout', false, { targetingKey: 'u2' }),
        false,
      );
      await client.shutdown();
    });
    ```

    Node extras: `fault: { kind: 'Timeout' }` fails every resolve with that kind; `initError: 'Configuration'` fails `initialize()` (runtime → `FATAL`).
  </Tab>
  <Tab title="Python">
    ```python

        EvaluationContext,

    def test_beta_cohort_gets_new_checkout():

            "new-checkout": {

                "value": True,

            "new-checkout", False, EvaluationContext("u2", {})
        ) is False
        client.shutdown()
    ```
  </Tab>
  <Tab title="Go">

## Protocol test server

Zero-dependency Node stub, loopback-only by default:

```bash
node test-server/implementation/server.mjs            # http://127.0.0.1:3901
node test-server/implementation/server.mjs --port 4000
```

### Routes that exist

| Method | Path | Role |
| --- | --- | --- |
| `POST` | `/v1/flags/evaluate` | Evaluate |
| `POST` | `/v1/capture` | Capture batch |
| `GET` | `/health` | `{ "ok": true }` |

**Not implemented:** `POST /v1/targets/register`.

The stub also still serves legacy vendor routes (`POST /flags?v=2`, definitions poll, `/batch/`) for historical harnesses. No shipped SDK talks those paths.

Auth on Fireweave routes: `Authorization: Bearer <key>`. Any non-empty key is accepted unless you configure one. Use obviously fake keys (`project-api-key_dev`).

The stub serves **its own** fixture keys (`fw-bool-on`, and others from `test-server/fixtures/flags-v2-success.json`). Keys your app expects resolve `FlagNotFound` → default unless you replace fixtures.

Point `initFireweave({ mode: 'remote', apiUrl, apiKey })` at `http://127.0.0.1:3901`. Your application reads `FW_API_URL` if you want; the SDK does not.

### Faults and assertions

| Call | Effect |
| --- | --- |
| `POST /_test/fault` | Inject `delay`, `401`, `429`, `500`, `invalid_json`, `truncated`, `quota_limited` |
| `POST /_test/reset` | Restore fixtures, clear faults/events |
| `GET /_test/events` | `{ fwEvents }` from `POST /v1/capture` |
| `GET /_test/requests` | Which routes the adapter called |

Per-request: header `X-Fw-Test-Fault: <mode>` or query `?fault=<mode>`.

## What to assert

- On / off / no-match → value, variant, `reason`.
- Missing key on remote → default + `FlagNotFound` (never a throw).
- Missing key on local → default + `DEFAULT` (never an error).
- Type mismatch → default + `TypeMismatch`.
- Missing `targetingKey` with `requireTargetingKey` → default + `TARGETING_KEY_MISSING`.
- Before init / after shutdown → default + `NotReady` / `AlreadyClosed`.
- Local `registerTarget` → `{ ok: true }` and a readable recorded set.
- Do **not** assert target registration against InMemory or the test-server stub.

## CI

Cross-language fixtures live in `contracts/`. Surface parity is `conformance/surface/control-points.surface.json`. That suite is for SDK contributors — application tests should use local mode or `InMemoryAdapter` (or the stub for HTTP).
