## Settings the start profile reads

The [start profile](/sdks/start-profile) reads these. The core API (`initFireweave` and its equivalents) reads none.

| Setting | Server apps | Browser and mobile apps (at build time) |
| --- | --- | --- |
| Key | `FIREWEAVE_KEY` (server key) | `FIREWEAVE_BROWSER_KEY` (browser key) |
| Endpoint | `FIREWEAVE_URL` | `FIREWEAVE_URL` |
| Environment name | `FIREWEAVE_ENV`, then `APP_ENV` | `FIREWEAVE_ENV` |

With no key, the SDK runs locally only when the environment name is `development`, `dev`, `local` or `test`. Anywhere else, a server app fails at start; a browser or mobile app serves defaults and reports the missing key.

<Warning>
  `FW_PROJECT_API_KEY` and `FW_API_URL` are no longer read. Rename them to `FIREWEAVE_KEY` and `FIREWEAVE_URL`; the values don't change.
</Warning>

## Wire paths

SDKs call three routes with `Authorization: Bearer <key>`. See [HTTP API](/reference/http-api).

| Method | Path |
| --- | --- |
| `POST` | `/v1/control-points/evaluate` |
| `POST` | `/v1/capture` |
| `POST` | `/v1/targets/register` |
