---
title: "HTTP API"
description: "Fireweave's two HTTP planes: the runtime routes your SDK calls, and the management routes for projects and environments."
---

Fireweave has two HTTP planes. Each takes its own kind of key, and a key for one never opens the other.

| Plane | Who calls it | Key |
| --- | --- | --- |
| Runtime | Your app, through an SDK | Server key, or a browser key in web apps |
| Management | Scripts, CI and [Terraform](/infrastructure/terraform/overview) | Org API key (`fw_org_…`) with the **Management** scope |

Send the key as `Authorization: Bearer <key>`. The production server is `https://app-server.fireweave.ai`.

## Runtime plane

Use an SDK for evaluate, capture and register. No SDK calls batch, unset or delete, so call those from your server with a server key. These routes accept requests from any browser origin.

| Method | Path | Does |
| --- | --- | --- |
| `POST` | `/v1/control-points/evaluate` | Evaluate control points |
| `POST` | `/v1/capture` | Record exposures and events |
| `POST` | `/v1/targets/register` | Register a user or device for targeting |
| `POST` | `/v1/targets/batch` | Register up to 1,000 targets in one call (server key only) |
| `POST` | `/v1/targets/unset` | Clear up to 100 named properties from one target (server key only) |
| `POST` | `/v1/targets/delete` | Remove one target from the key's environment (server key only) |

The key decides the environment. `/v1/targets/register` ignores an `environment` in the body: a key bound to an environment tags the target with that environment, and an unbound key tags it with the project's default.

Properties sent with a server key are trusted. Properties sent with a browser key never are, so cohort rules don't match them.

```bash
curl https://app-server.fireweave.ai/v1/targets/batch \
  -H "Authorization: Bearer $FIREWEAVE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"targets":[{"targetingKey":"user_42","kind":"user","properties":{"plan":"pro"}}]}'
```

## Management plane

The organization always comes from the key, never from the path.

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `/v1/whoami` | Who the key belongs to: `userId`, `orgId`, `scope` |
| `GET` `POST` | `/v1/projects` | List or create projects |
| `GET` `PATCH` `DELETE` | `/v1/projects/{projectId}` | Read, update or delete a project |
| `GET` `POST` | `/v1/projects/{projectId}/environments` | List or create environments |
| `GET` `PATCH` `DELETE` | `/v1/projects/{projectId}/environments/{envId}` | Read, update or delete an environment |
| `GET` | `/v1/projects/{projectId}/control-points` | Control points that merges have registered |
| `GET` | `/v1/projects/{projectId}/control-points/graph` | The same, with recorded dependency edges |

`DELETE /v1/projects/{projectId}` is permanent: it removes the project's environments, keys, rollouts and control points.

```bash
curl https://app-server.fireweave.ai/v1/projects \
  -H "Authorization: Bearer $FW_ORG_API_KEY"
```

A **CI read** key reads only what [`fw sync`](/cli/ci) needs, plus `/v1/whoami`. It can't manage projects or environments.

## Errors

### Management errors

```json
{ "error": { "code": "NOT_FOUND", "message": "Project not found" } }
```

| Status | When |
| --- | --- |
| `401` | Missing or invalid key |
| `403` | The key's scope, or the role of the person who created it, doesn't allow the call |
| `404` | Unknown id, or an id in another organization |
| `409` | A slug that already exists; archiving or deleting a project, or deleting an environment, while a rollout is live (`LIVE_ROLLOUTS`); changing an archived project (`PROJECT_ARCHIVED`); a change that would stop Fireweave enforcing its readiness check on a branch (`MERGE_GATE_REF_ENFORCED`: sign in as an Owner or Admin instead) |

### Runtime errors

```json
{ "ok": false, "error": "TARGETING_KEY_TOO_LONG" }
```

| Status | Code | When |
| --- | --- | --- |
| `400` | `TARGETING_KEY_TOO_LONG` | A `targetingKey` over 120 characters on evaluate or register. `/v1/capture` drops that event instead. |
| `400` | `VALIDATION` | A body that batch, unset or delete can't accept |
| `400` | `TOO_MANY_EVENTS` | More than 500 events in one `/v1/capture` call |
| `400` | `EVENT_NAME_RESERVED` | An event name that starts with `$` |
| `400` | `TOO_MANY_PROPERTIES` / `PROPERTIES_TOO_LARGE` | A target with more than 100 properties, or more than 64 KB of them |
| `403` | `SERVER_KEY_REQUIRED` | Batch, unset or delete called with a key that isn't a server key |
| `429` | `RATE_LIMITED` | Over the key's per-minute limit. Wait for `Retry-After`. |
| `429` | `DAILY_LIMIT_REACHED` | Your organization hit its daily limit of evaluate and capture calls |

Cohorts, targets and rollout strategies are managed in the web app; they have no management-plane route. Routes not listed here are not part of the public contract and may change.
