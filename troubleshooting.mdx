title: "Troubleshooting"
description: "Common problems and the fix for each."
---

Start with `fw doctor`. It checks your install, sign-in and repo, and prints a fix for each problem it finds.

## Setup

| Symptom | Fix |
| --- | --- |
| The setup PR never opened, or the run stopped | Open **Project Setup** in the sidebar. Answer any questions and choose **Save and rerun**, or choose **Retry**. |
| You'd rather not wait on the cloud run | Choose **Set up locally instead**. Fireweave closes its setup PR and shows the commands to run. See [Set up Fireweave](/setup). |
| The setup PR was closed without merging | Nothing changed in the repo. Choose **Open a new PR** under **Project Setup**. |
| The app fails at start, naming `FIREWEAVE_KEY` | The deploy has no key. Set `FIREWEAVE_KEY` (or `FIREWEAVE_BROWSER_KEY` for a browser app) in that environment. See [Keys](/connect/keys). |

## The fw CLI

| Symptom | Fix |
| --- | --- |
| `fw: command not found` after installing | Open a new terminal. Still missing? Run `~/.fireweave/bin/fw doctor --fix`. |
| `fw` says you're not signed in | Run `fw login`, then `fw status`. |
| `fw status` says no project is linked | Run `fw select-project` in a repo a setup PR set up, or `fw init` otherwise. |
| CI refuses `FW_ORG_API_KEY` | Use a CI key (`fw_org_…`), not your app's key, and make sure `.fireweave/project.json` is committed. See [Run in CI](/cli/ci). |

## Your coding agent

| Symptom | Fix |
| --- | --- |
| The agent ignores Fireweave | Run `fw agents status`. If it says off, run `fw agents on`. If you're signed out, run `fw login`. |
| The agent has no Fireweave skills | Install the plugin. See [Set up your coding agent](/agents/setup). |
| The agent won't finish and names a control point or manifest | Fireweave's check found a change without its control point. Ask the agent to fix what the message names. |
| The agent is refused because a teammate holds the feature | Your project uses feature coordination. See [Working as a team](/agents/team-coordination). |

## Pull requests and rollouts

| Symptom | Fix |
| --- | --- |
| The readiness check says not ready | Open the check on the PR. Each finding says what to change; ask your agent to fix them and push. |
| No rollout appeared after merging | Rollouts are registered when you merge into an environment branch. Check the PR's base branch, and see [Environments](/connect/environments). |
| A rollout sits at **Waiting for Start** | That's expected. Deploy, then press **Start rollout** in the web app. |
| A rollout went to **Breached** | A guardrail tripped. What happens next depends on its **On breach** setting. See [Guardrails](/ship/guardrails). |

## SDKs

| Symptom | Fix |
| --- | --- |
| Every control point returns its default | A control point stays off until someone starts its rollout. Also check the app has its key: with no key, a `development` or `test` environment runs in local mode. |
| `ControlPointNotFound` | FireWeave doesn't know that key yet. It is registered when the change merges into an environment branch. Otherwise, check the key for a typo. |
| `Must use import to load ES Module`, `ERR_REQUIRE_ESM`, or `TS2307` on `@fireweaveai/server-sdk/start` | Your toolchain loads CommonJS. Use a CommonJS twin. See [CommonJS projects](/sdks/commonjs). |
| Code still reads `FW_PROJECT_API_KEY` | SDK 3.0 reads `FIREWEAVE_KEY` only. See [Migrate to 3.0](/sdks/migrate-3). |

Still stuck? Run `fw feedback` to send Fireweave a report.
